# TPU SFT 实验可视化图表说明

> 模型: Qwen2.5-Coder-1.5B + LoRA | 硬件: TPU v2-8 (4 chips) | 数据: GSM8K-CoT
> 生成脚本: `generate_figures.py`

## 图表 (Figures)

### fig1_accuracy.png — 准确率 + McNemar 检验

- **左图**: SFT 前后 GSM8K 数学题准确率对比
  - Baseline 57.8% → Fine-tuned 66.0%，提升 **+8.1%**
  - p < 0.0001，统计极显著
- **右图**: McNemar 不一致对分析
  - 129 道题 SFT 后「退步」（原来对、现在错）
  - 236 道题被「修复」（原来错、现在对）
  - 净增 **+107 道题**，说明 SFT 收益远大于损失

### fig2_training.png — 训练动态

- **左图**: 每步训练耗时（对数轴）
  - 第 1-2 步是 XLA JIT 编译（85s + 88s），之后迅速降到 84ms 稳态
  - 每 ~336 步出现一次 ~500ms 毛刺，原因是 Python GC（垃圾回收），正常现象
- **右图**: 训练吞吐量（50 步滑动平均）
  - 稳态 ~24.3K tokens/sec，非常平稳
  - 周期性锯齿是 GC 毛刺经滑动平均窗口放大的效果

### fig3_time_breakdown.png — 时间拆解对比

- 左右两个方案并排对比: **batch=1（旧）** vs **batch=16（新）**
- 推理是最大瓶颈: 30.7 min → 15.7 min（batch 推理加速 ~2x）
- 整个 pipeline: ~41 min → ~24 min
- 训练本身只要 2.6 min，JIT 编译 ~4.5 min 是固定开销

### fig4_hardware.png — 硬件利用率 + 配置卡

- **左**: MFU（Model FLOPs Utilization）条形图，达 **83.4%**，TPU 算力利用充分
- **中**: 实际 37.5 TFLOP/s vs TPU v2 理论峰值 45 TFLOP/s 的柱状对比
- **右**: 实验配置一览卡（模型、LoRA 参数量、硬件、batch size、吞吐量等）

### fig5_data_scaling.png — 数据量对比

- **左图**: 3000 条 vs 7465 条训练的准确率柱状对比
  - 3000 条: +6.0%，p = 0.105，**不显著**（红色标注）
  - 7465 条: +8.1%，p < 0.001，**显著**（绿色标注）
- **右表**: 总结对比，红色 NO vs 绿色 YES，直观展示数据量对统计显著性的影响
- **核心结论**: 训练只多 1.5 分钟，但统计显著性从 NO 变成 YES

### fig6_inference_opt.png — 推理优化效果

- **左图**: 每条推理延迟对比
  - batch=1: 700ms/条 vs batch=16: 358ms/条，**加速 2x**
- **右图**: 不同评估样本量下的总 pipeline 时间投影（200 / 500 / 1316 条）
  - 评估量越大，batch 推理的收益越明显

### fig7_dashboard.png — 一页总览仪表盘

6 个面板浓缩所有关键结果，适合作为**单页展示**:
- (0,0) 准确率柱状图 + 提升幅度
- (0,1) MFU 环形图 (83.4%)
- (0,2) 关键性能数字一览
- (1,0) 步耗时曲线（JIT spike → 稳态）
- (1,1) 时间拆解饼图（推理 65%、JIT 19%、训练 11%）
- (1,2) McNemar 不一致对柱状图

## 表格 (Tables)

### table1_results.png — 主要实验结果

实验全貌一览:
- 模型、硬件、数据集、训练配置
- 准确率: 57.8% → 66.0%（+8.1%，+107 道题）
- McNemar χ² = 30.78，p < 0.0001，统计极显著
- 适合放在 slides 第一页作为**结果总结**

### table2_performance.png — TPU 训练性能

所有硬件性能指标汇总:
- MFU 83.4%（37.5 / 45 TFLOP/s per chip）
- 吞吐量 24,314 tok/s
- 稳态步耗时 84ms，JIT 首步 85s
- 总 pipeline ~24 min（含 batch=16 推理）
- 适合讨论 **TPU 硬件利用效率**

### table3_data_scaling.png — 数据量对比

3000 条 vs 全量 7465 条的完整对比:
- 最后两行红绿对比: NO vs YES
- 关键发现: 训练只差 1.5 分钟，统计显著性从不显著变为极显著
- 适合和老师讨论**数据量选择策略**

### table4_inference_opt.png — 推理优化 + 方案时间估算

两个子表:
- **4a**: batch=1 vs batch=16 的加速效果（2x），pipeline 从 41min → 24min
- **4b**: 三种教学方案的时间估算
  - A: 快速课堂演示 (~10 min, 200 条评估)
  - B: 平衡方案 (~14 min, 500 条评估)
  - C: 完整实验 (~24 min, 1316 条评估)
