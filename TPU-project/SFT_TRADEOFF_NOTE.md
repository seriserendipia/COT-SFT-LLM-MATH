# SFT 数据量选择：3000 条 vs 全量 7465 条

## 核心问题

作为教学项目，我们需要在「跑得快、课堂可操作」和「效果明显、统计可信」之间做选择。
以下是两组实际跑出来的实验数据，供讨论。

---

## 实验结果对比

### 准确率

| | 3000 条训练 | 7465 条训练（全量） |
|---|---|---|
| Baseline（SFT 前） | 61.5% (123/200) | 57.8% (761/1316) |
| Fine-tuned（SFT 后） | 67.5% (135/200) | 66.0% (868/1316) |
| **提升幅度** | **+6.0%** | **+8.1%** |

> 注：两次实验的 Baseline 不同是因为评估集不同——3000 条实验只用了 200 条测试集，全量实验用了完整 1316 条测试集，更大的测试集给出了更稳定的 Baseline 估计。

### 统计显著性

| | 3000 条训练 | 7465 条训练（全量） |
|---|---|---|
| 测试方法 | McNemar's test | McNemar's test |
| 评估样本数 | 200 | 1316 |
| χ² | — | 30.78 |
| p-value | 0.105 | **< 0.0001** |
| **统计显著？** | **NO**（p > 0.05） | **YES**（p < 0.001） |
| 不一致对：仅 baseline 对 | — | 129 |
| 不一致对：仅 finetuned 对 | — | 236 |

关键区别：3000 条训练 + 200 条评估，提升看起来有（+6%），但在统计上**不能排除随机波动**。全量训练 + 1316 条评估，提升（+8.1%）是**确定性的**，p < 0.0001。

### 性能指标

| 指标 | 3000 条训练 | 7465 条训练（全量） |
|---|---|---|
| 训练步数 | 750 steps (1 epoch) | 1866 steps (1 epoch) |
| 稳态步耗时 | ~0.083s | 0.084s |
| 训练时间（不含编译） | ~62s (~1 min) | ~157s (~2.6 min) |
| JIT 编译开销 | ~165s | 173s |
| MFU | ~83% | 83.4% |
| 吞吐量 | ~24,000 tok/s | 24,314 tok/s |

> 可以看到，**训练本身只差 ~1.5 分钟**（1 min vs 2.6 min）。性能指标（MFU、吞吐）基本一致，说明训练效率不受数据量影响。

## 时间开销分析

### 推理优化：batch=16 批量推理

原始实现是逐条推理（batch=1），TPU 利用率极低。改为 batch=16 后实测：

| 指标 | batch=1（旧） | batch=16（新） |
|---|---|---|
| 稳态每条耗时 | 0.700s | **0.358s** |
| 首次推理 (JIT) | ~43s (1 条) | ~51s (16 条) |
| **加速比** | — | **~2x** |

> batch=16 加速约 2x 而非理论上的 16x，是因为 decode 阶段（逐 token 自回归生成）是 memory-bandwidth bound，batch 增大加重了 KV cache 的 HBM 读取负担。不过 prefill 阶段确实受益于 batch 并行。

### 按 batch=16 重新估算各方案时间

| 阶段 | 200 条评估 ×2 | 500 条评估 ×2 | 1316 条评估 ×2 |
|---|---|---|---|
| 模型加载 | 16s | 16s | 16s |
| JIT 编译（推理 ×2） | ~102s | ~102s | ~102s |
| 推理（稳态） | 200×2×0.36 = 2.4 min | 500×2×0.36 = 6 min | 1316×2×0.36 = 15.8 min |
| JIT 编译（训练） | ~173s | ~173s | ~173s |
| SFT 训练 | 2.6 min | 2.6 min | 2.6 min |
| **总计** | **~10 min** | **~14 min** | **~24 min** |

对比旧版（batch=1 推理）：

| 方案 | batch=1（旧） | batch=16（新） | 节省 |
|---|---|---|---|
| 200 条评估 | ~13 min | ~10 min | 3 min |
| 500 条评估 | ~23 min | ~14 min | 9 min |
| 1316 条评估 | ~41 min | **~24 min** | **17 min** |

> 全量跑从 41 min 降到 24 min，节省了 17 分钟。评估样本越多，batch 推理的收益越大。

### 时间去向拆解（全量 + batch=16）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| 模型加载 | 16s | 1% |
| JIT 编译（训练 + 推理） | ~275s | 19% |
| SFT 训练 | ~157s | 11% |
| **推理评估（1316 条 ×2）** | **~16 min** | **66%** |
| 其他 | ~1 min | 3% |

推理仍然是最大的时间消耗，但占比从 76% 降到了 66%。

## 可选方案（按 batch=16 估算）

全部方案训练量都用全量 7465 条——因为训练只差 1.5 分钟，没理由省。

### 方案 A：快速课堂演示（~10 min）
- 训练：全量 7465 条
- 评估：200 条
- 优点：课堂时间可控，学生能亲手跑
- 缺点：200 条评估的提升可能不显著

### 方案 B：折中（~14 min）
- 训练：全量 7465 条
- 评估：~500 条
- 优点：时间合理，统计量应足够检出显著性
- 缺点：需要验证 500 条是否真的够

### 方案 C：完整实验（~24 min）
- 训练：全量 7465 条
- 评估：全量 1316 条
- 优点：结果扎实，p < 0.0001，可用于正式报告
- 缺点：24 分钟对课堂来说中等偏长

---

## 建议

1. **训练数据不缩减**——3000→7465 只多 1.5 分钟，准确率提升从 +6%→+8.1%，显著性从 NO→YES。

2. **评估样本数是决定总时间的关键**——推理占总时间的 66%。

3. **batch=16 已经把推理加速了 2x**——全量 1316 条评估从 31 min 降到 ~16 min，整个 pipeline 从 41 min 降到 ~24 min。

4. **如果课堂时间 ≤ 15 分钟**→ 方案 A 或 B。全量训练 + 200~500 条评估。

5. **如果课堂时间 ~25 分钟或用于作业/报告**→ 方案 C。全量训练 + 全量评估，结果有完整统计检验。
